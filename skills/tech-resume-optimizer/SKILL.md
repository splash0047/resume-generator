# Tech Resume Optimizer

## Review Layers

### 1. Eligibility
Check job-specific hard requirements before optimizing wording.

### 2. Parsing
Ensure:
- text-based PDF/DOCX;
- standard headings;
- sensible reading order;
- contact and education information extract correctly;
- no unnecessary graphics or layout complexity.

### 3. Technical Evidence
Prioritize:
- implemented systems;
- APIs;
- databases;
- architecture;
- tests;
- reliability/security work;
- reproducible evaluations.

### 4. Role Relevance
Use one technical identity per resume variant. Reorder projects and skills around the target role.

### 5. Human Readability
A reader should be able to identify the primary stack and strongest evidence quickly. Do not use a fixed attention-span claim.

### 6. Links
Repositories and demos must open and visibly support stated claims.

## Technical Resume Rules

- expected graduation is explicit for new-grad roles;
- 2–3 strong projects usually beat a long weak list;
- implementation details can be strong without metrics;
- metrics require provenance;
- credentials are not substitutes for project/work evidence;
- do not list tools the candidate cannot discuss.

## Output

- Parsing findings
- Eligibility findings
- Strongest evidence
- Weak/unsupported claims
- Role-specific content changes
- Project and skill ordering
- Export validation checklist

## Guardrails

- No universal ATS score.
- No claim that the resume "passes ATS".
- No hiring prediction.
- No keyword-density target.
